# 跟人说话：第一轮回复与 M3 确认单

## 第一轮只允许四件事

```
1. 我听到的原话（逐字，≥3 条，不加解释）
2. 我推出的目标与损失（每条标 stated / inferred / measured）
3. 这次不做的事（3~5 条非目标，每条指向一个会被砍掉的功能）
4. 需要你回答的问题（≤3 个，每个都是封闭问题）
```

**禁止**：给方案、给页面、给字段、给结论、写「我建议做成…」、写「整体架构」。

自检：第一轮回复里出现「页面」「按钮」「字段」「模块」「功能」任一，重写。

**为什么这么硬**：用户给的第一句话里 80% 是方案。第一轮就给方案，等于承认那个方案是对的，后面五步变成给它找理由。

## M3 确认单：三分钟拍板

场景表可能有 16 条，倒给他不会看。确认单只给三类东西，控制在 7 条以内：

```markdown
### 场景拆完了，要你拍 4 件事，3 分钟够

**一、我按十个维度扫了一遍，一共 16 条场景，其中 P0 6 条**
（挡住生产的 6 条：S1 取样 / S2 紧急放行 / S3 先检后入 / S4 判定 / S5 不合格处置 / S6 报告交付）

**二、有 4 处我拿不准，你一句话就能定**（不定我按建议先做，改起来要返工）：

| # | 拿不准的 | 我的建议 | 你不定会怎样 |
|---|---|---|---|
| Q1 | 交接班时上一班没提交的单据算谁的 | 算提交人，跨班不转移 | 单子卡在两班之间，谁都不认 |
| Q2 | 供应商批次号断号时按什么抽检 | 按收货流水号抽 | 抽检基准失效，可能漏检也可能重复检 |

**三、这三个我替你定了，你不反对就这么执行**：
1. 检验标准由技术部用 Excel 维护，系统只导入与冻结版本
2. 供应商本期无账号，只收 PDF
3. 控制图数据只取检验记录一个源

**回我一句就行**：上面 4 条怎么定 + 场景有没有漏。
```

三条硬规则：

1. **P0 必须点名列出**（≤6 个），让他看见哪些是挡生产的。全列 16 条等于没列。
2. **待确认 ≤7 条，每条自带建议和后果**。只给问题不给建议，是把判断工作推回去。
3. **默认值单独一段**，写清「现在说还来得及」。

## 术语一律换成人话

| 专业说法 | 对他说 |
|---|---|
| 场景穷举 / 覆盖矩阵 | 十个角度都扫过一遍，每一格都有交代 |
| 状态机 / from→to | 单据状态怎么流转 |
| 降级路径 | 走不通时你们实际会怎么做 |
| 幂等 | 点两次不会出两条记录 |
| 现场使用者 | 车间里真正干活的人 |

## M1 与 M6 的两种汇报

| 卡点 | 第一句必须是 | 结尾只问 | 不要出现 |
|---|---|---|---|
| M1 真问题 | 带数字的损失（「21 天里有 9.4 天在等人」） | 认不认这个方向 | 页面名、字段名、模块名 |
| M6 结论 | 我过了 40 个疑问，只剩 3 件事要你定 | 这三件谁去办、什么时候办 | 把 40 条全倒出来 |

## 用户说「你就按我说的做」怎么办

先记下来，再给他一次退出的机会：

```markdown
你要求按你给的结构做，我按你说的做，但记一笔：
- 角色表保持六列，另起一张《现实性核对》表（你没提，但「质量总监是空的」这类问题只有这张表能抓）
- 如果这张表你也不要，我整表填 N/A 并在豁免说明写原因，不算我偷偷跳过
```

**「记一笔」比「说服他」有效**：他要的是被尊重，不是被教育。
