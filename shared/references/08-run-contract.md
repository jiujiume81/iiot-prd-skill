# 执行约束（可直接贴进任意 agent 的指令里）

**极简版（48 字，贴这一句就够）**

> 开工 next 读目标原句，每步贴 brief 进度块；完成须有真实产物文件；被拦不换说法重试。

下面是要展开时用的完整版。

> 这条 prompt 只讲「怎么干活」，不讲业务。业务由各自的 SKILL 负责。
> `$SUITE` 换成套件根目录；`D` 是产出目录（`analysis/<产品>/`）。

## 一、开工先读账本

每次会话第一件事、以及每个子任务完成后：

```bash
$SUITE/shared/bin/harness.py next --dir D
```

打出**目标原句 / 当前位置 / 下一步 / 三条约束**。不许凭记忆说「上次做到哪」。

## 二、每步贴进度块

```bash
$SUITE/shared/bin/harness.py next --dir D --brief
```

返回 3 行，**原样贴进回复正文**，不概括、不省略：

```
── 1/3 ──────────────────────────────
A1 ✓  A2 ← 现在  A3
做 A2 角色 → M2-roles.md ｜ 账本 4 步
```

用户看的是这个块，不是你的总结段落。界面任务列表靠不住（依赖宿主），文字才是落点。

## 三、有产出才记一步

```bash
$SUITE/shared/bin/harness.py step --dir D --taskId <id> \
    --intent "<判断>" --tool <工具> --args "<关键参数>"
```

`--intent` 写**结论**不写动作：

- ✅「从三份纪要里看出真问题不是缺按钮，是没人对留样负责」
- ❌「读了 M1」「查了 M3」

**不算一步**：纯检索、grep 找位置、翻目录、再跑一遍 status。
**算一步**：读材料得出结论、写/改产物、跑校验并解释结果、开评审。

## 四、完成由产物决定

```bash
$SUITE/shared/bin/harness.py step --dir D --taskId <id> --intent "..." \
    --tool Write --args "..." --out <产物文件> --done
```

文件必须**真实存在**、`doneWhen` 点名的串必须**出现**，否则 exit 6，任务不推进。

里程碑自检是**只读**的：它回答「偏没偏」，不回答「完没完」，不给任何任务打勾。

## 五、三种异常，三种动作

| 退出码 | 含义 | 你该做什么 |
|---|---|---|
| **4** | 跳步（遗忘） | 读 `next` 的注入块，回它说的那步，**不要重开** |
| **3** | 偏离（意图与任务不沾） | 停手，把目标原句念一遍；确要做就 `amend` 走审批 |
| **2** | 循环（同一动作第 3 次） | **立刻停**。不许换措辞重试。写清卡在哪，交给用户 |

单次偏离只 WARN 放行；**连续 3 次**才判偏移——因为「真实发现」和「跑偏」在意图句上长得一样。

## 六、新增步骤要过审

```bash
$SUITE/shared/bin/harness.py amend --dir D --add "<新步骤>" --why "<出处>"
```

对不上目标 → exit 3。`--why` 必须有真实出处（用户原话 / 纪要 / 工单），**「觉得需要」不算**。

## 七、四条禁令

- 不手改 `_state.json` / `proto.json` / `_run/*.json` —— 它们只经脚本写
- 不把界面任务列表反写进 `_run/` —— 列表是投影，`_run/` 是真相，单向
- 不用 `--force` 绕过判据 —— 它只能覆盖「已签收」这类状态，不能覆盖判据结果
- 被拦住后不换说法重试 —— 那是模型的默认反射，也是这套约束最想禁的一条
