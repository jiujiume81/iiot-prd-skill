# iiot-business-analysis — 业务分析（第 1 段）

这一段只回答三个问题：**这事该不该做、谁在里头、到底有多少种情况**。三个问题没答案，后面写什么都是给假设镶边。

> ```bash

`--stage 1` 跑 24 条本段判据 + 6 条跨阶段判据（`A-00`、`A-60`~`A-64`）。**24 条全绿不算过**，要算上那 6 条。

### 出口的机读三件，缺一件 02 就会重抄

```jsonc
"export": {
  "p0": [ {"id":"S-03","name":"…","why":"…","srcRef":"M3-scenarios.md#场景表"} ],
  "roles": [ {"id":"u-qa","name":"检验员","exists":true,"srcRef":"M2-roles.md#R-02"} ],
  "openQuestions": [ {"id":"Q-01","text":"…","suggest":"…","resolved":null} ]
}
```

| 字段 | 02 会拿它干什么 | 硬约束 |
|---|---|---|
| `p0[]` | 只给 P0 建流程 | 条数必须等于 M3 场景表的 P0 行数，差一条就红 |
| `roles[]` | 直接映射成契约里的 `actor`，不再自己起名 | 每个 id 要能回指 `M2-roles.md#R-xx` |
| `openQuestions[]` | 02 只许改 `resolved`／`resolvedBy`，不许改 `text`／`suggest` | 改了正文，`A-25` 第④重 hash 失配 |

**`p1` 故意不进 export**：P1 清单已经在 M3 场景表的「优先级」列里，再复制一份进 export 就有两份，M3 改一处、export 忘一处就漂——上次来料模块大改就是这么来的。所以 `A-35` 直接从 M3 的 P1 行读，02 逐条给它找下落（进 M4 流程，或进 M6 后置批次并写明理由与兜底），找不到才红。**P1 允许不做，不许没下落。**

## 三、M3 是唯一的硬闸门：五重

喊「场景没遗漏」不算数。`_state.json` 里要有五样东西（`A-25`）：

| 重 | 字段 | 挡什么 |
|---|---|---|
| ① 有人 | `confirmations.M3.by` 非空且不含 AI/模型/助手/Claude/GPT | 模型替用户签字 |
| ② 有时 | `.at` 是合法 ISO8601 且不在未来 | 时间写到未来，mtime 判据恒绿 |
| ③ 有据 | `.quote` ≥4 字，含 `S\d`／维度名／「没遗漏」／≥2 个业务实词 | 用一句「好的」冒充确认 |
| ④ 对版 | `.contentHash` = M3 去掉「确认记录」节后的 sha256 前 12 位 | **确认后又偷偷改场景表**——mtime 挡不住，hash 挡得住 |
| ⑤ 未跳步 | `M4` 不存在，或 mtime ≥ `M3.at` | 先写完第 4 步再回头补签 |

拦下时照这个句式回用户，不要自己找台阶：

```
M3 闸门未通过：[具体哪一重]。场景表共 16 条，其中 P0 6 条，待确认 4 条。
请回我一句「场景没遗漏，可以继续」，并确认这 4 条待确认怎么定，我再往下做第 4 步。
```

穷举的判法只有一条：**每个格子都有交代**。82 格是脚本按取值表实时求和出来的（`Σ 启用维度的取值数`），关掉一维分母自动变，不认手写数字。空格 0、排除 ≤40%、场景 ≥15 条、P0 ≥5 条、待确认 ≤7 格。
