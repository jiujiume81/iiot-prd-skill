## 一、进来先判断我在哪一段

| 现场 | 判定 | 动作 |
|---|---|---|
| 没有 `_state.json`，或 `stages[1].status != done` | 上游没做完 | **不接活**。回一句"业务分析那三步还没签闸门"，给出 01 的命令 |
| `current.stage = 2` | 是我的段，可能做到一半 | 从第一个非 `done` 的步继续，不重开 |
| `stages[2].status = done` | 本段已完成 | 不重做，念 §五 的交接话术，把 03 的命令给出去 |

两条不能通融的：

- **`stages[1].status = done` 但 M3 的 `contentHash` 与当前 M3 文件不符** → 场景表被人改过，闸门作废，回 01 重签。不许"我顺手对齐一下"。
- 用户直接甩一句「帮我重新分析下这个需求」→ 那是 01 的活，**不要在本段重扫场景**。本段只消费 `export.p0` / `export.roles`；P1 清单从 M3 的优先级列直接读，不从 export 拿。


三件事必须说清：

1. **`--half req` 绿不等于契约成立**，只等于"需求这一半没矛盾"。03 交付前要跑不带 `--half` 的全场。
2. **02 交出去的东西不只给机器看**。业务方要签字，就得有一份能读的：用 `build_prd.py`（属 03 的工具，弱依赖，`--shaping` 可不传）生成 md，第 1~6 章有效；页面章节因骨架未填 `prd` 而空，属预期，不要为了填满它去写页面。
3. `--stage 2` 之前先跑 `--status`。状态显示上游未完成时，**先停下来说清楚**，不要用"我补一份 M3"绕过。

## 三、落契约的六条硬线

契约是这一段唯一的下游接口，写歪一条，03 全部白做。

| # | 硬线 | 怎么写 | 谁判红 |
|---|---|---|---|
| 1 | **一个动作 = 一个状态 = 一条命令** | 待排查／待分析／待下发／措施执行中／待验证／待审批，各自一条 `capability`，各自带 `actor` | `L2-54`~`L2-58` |
| 2 | **状态机端点不许悬空** | 每条 `from`/`to` 都能在状态集里找到；非终态必须有出向命令，否则单据永久卡住 | `L2-57`、状态机端点 |
| 3 | **四眼原则** | `stage` 为 `submit` 与 `verify` 的命令，`actor` 交集必须为空；要一人多角色必须显式 `sameActorOk` | 四眼判据 |
| 4 | **EARS 六字段一个不能省，且必须有非法路径** | 角色（岗位不用人名）/ 触发 / 规则 / 状态机 / 预期（单一响应）/ 验收（≥1 条 `kind:"illegal"`：状态不符、权限不足、并发冲突） | `L2-34` |
| 5 | **字段主档只登记被人点名过的字段** | M1/M3/M5 里出现过的业务字段才进 `fieldCatalog`，`dataSources` 要能解析到源表 | 字段主档与取数链路 |
| 6 | **切片要能独立验收** | 每批有范围、有依赖、无成环；一次做完必然后几页糊 | `P-01`~`P-11` |

**两处是 03 的活，本段不许写**：

| 键 | 归属 | 理由 |
|---|---|---|
| `capabilities[].ui`（`kind` / `entry` / `title` / `fields`） | 03 | 判定的是"这个动作用什么界面承载"，属渲染决策（`L2-55` 归 03） |
| `pages[].componentTree`、`pages[].prd`、`pages[].interactions` | 03 | 本段只给页面**骨架**：`id` / `moduleId` / `target` / `route` / `title` / `layout` / `entity` |

### M4 必须有「P1 未上流程」专节

这是上一轮最容易漏的地方：01 只把 P0 交给本段，P1 场景就会在这里**静默消失**——不报错、没人问、上线才发现缺一块。

规矩：**允许不上流程，不许没有下落。** 每个 P1 场景只有两条去向，二选一：

| 去向 | 写在哪 | 要写什么 |
|---|---|---|
| 进流程 | `M4` 的流程或分支 | 正常写，不用额外解释 |
| 后置 | `M4` 的「P1 未上流程」专节，**或** `M6` 结论里的后置批次 | 为什么不在这批 + 落到哪一步兜底 |

```markdown
## P1 未上流程

| 场景 | 为什么不在这批 | 落到哪一步兜底 |
|---|---|---|
| S-11 退货复检 | 频次 2 次/月，本批只做日频 | 走线下纸质单，M5 异常 7 记录补录 |
| S-14 跨厂调拨检验 | 涉及另一套系统，二期 | 本批不做，M6 风险 3 已登记 |
```

判据 `A-35`（本段新增）：从 `M3` 场景表的 P1 行逐条找下落，**进流程或进后置清单，找不到就红**。P1 清单不另存一份——`M3` 的优先级列就是唯一源，复制一份到 `export` 里必然漂。
