## 5 「维度」列：留，但改四处

**结论：这列是本轮最好的设计，不并到别处。** 它把"场景是否穷举"从感觉变成可判，方向完全对。但现在的形态只做到了一半，四处必改（前三处是原判，第四处是实跑补的）：

### 5.1 原有的五族不是五个维度，是「三个维度 + 一个扫描对象 + 一个横切约束」

这是必须先说清的一件事。你的五族拆开看：

| 你的族 | 它其实是什么 | 归到哪 |
|---|---|---|
| `时间` | 真正的维度（同一动作在不同时点行为不同） | 保留为 `时间` |
| `空间` | 真正的维度，但它和"在哪儿操作、有没有网、戴不戴手套"是同一件事 | 并入 `现场` |
| `触发` | 真正的维度 | 保留为 `触发` |
| `对象` | **不是维度，是"扫谁"**——物料/设备/工单是扫描对象，不是场景的一个轴 | 提到扫描协议 Step 1 |
| `约束` | **横切项**。网络/环境属于 `现场`；权限/合规属于 `角色` 和 `版本` | 拆进 `现场` / `角色` |

所以五族实际只覆盖 3 个扫描轴。缺的轴里，正好有用户踩的两个坑所在的那两个：**来路**（先入后检 vs 先检后入）和**连续**（批次号断号）。用你的五族给这两条场景打标：

| 场景 | 用五族的标法 | 问题 |
|---|---|---|
| 先检后入 | `时间:正常班、空间:仓库、对象:物料、触发:计划、约束:合规` | 两条标法**完全一样** |
| 先入后检 | `时间:正常班、空间:仓库、对象:物料、触发:计划、约束:合规` | 标签区分不出来 |

标签是筛子，只能筛出"标过的"；它生不出"没想到的"。这就是 §5.2 要补覆盖矩阵的原因，也是族必须扩到 10 个的原因。

**两处改动是实跑逼出来的，不是想出来的**：

### 6.2 为什么 ④ 是你的方案里唯一的真缺口

你的 A-35 逻辑是"快照里不该出现后阶段文件"。它挡的是"六份一起写完再补签"。**它挡不住这个序列**：

1. 场景表 23 条写完 → `--confirm M3` → 快照正确（不含 M4/M5/M6），A-35 绿；
2. 用户看完说"再补两条" → 模型改场景表 → mtime 变了，但比 M3 晚，A-34 绿；
3. 画流程 → M4 的 mtime 晚于 M3，A-35 绿。

三步全绿，但"用户确认的那一版"和"实际执行的这一版"不是同一版。这是最容易发生、也最难事后发现的一种——因为场景表改完看着更好了，没人会回头核。

**第④重的实现（`A-25`）**：

```python
# --confirm M3 时
secs = sections(read(m3))            # 剔除 > 行
body = secs_without(secs, "确认记录")
gate["confirmations"]["M3"]["contentHash"] = sha256(json.dumps(body, sort_keys=True))[:16]

# check 时
cur = 同样的算法
if gate["confirmations"]["M3"].get("contentHash") != cur:
    add(E, "A-25", "M3-scenarios.md 在 M3 确认后被修改过（内容指纹不符）：确认的是旧版")
```

剔除「确认记录」节是必须的：确认时要把 quote 写进这一节，不剔除会自己把自己判红。
