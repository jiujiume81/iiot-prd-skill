### 出口的机读三件，缺一件 02 就会重抄

```jsonc
"export": {
  "p0": [ {"id":"S-03","name":"…","why":"…","srcRef":"M3-scenarios.md#场景表"} ],
  "roles": [ {"id":"u-qa","name":"检验员","exists":true,"srcRef":"M2-roles.md#R-02"} ],
  "openQuestions": [ {"id":"Q-01","text":"…","suggest":"…","resolved":null} ]
}
```

| 字段 | 02 会拿它干什么 | 硬约束 |
|---|---|---|
| `p0[]` | 只给 P0 建流程 | 条数必须等于 M3 场景表的 P0 行数，差一条就红 |
| `roles[]` | 直接映射成契约里的 `actor`，不再自己起名 | 每个 id 要能回指 `M2-roles.md#R-xx` |
| `openQuestions[]` | 02 只许改 `resolved`／`resolvedBy`，不许改 `text`／`suggest` | 改了正文，`A-25` 第④重 hash 失配 |

**`p1` 故意不进 export**：P1 清单已经在 M3 场景表的「优先级」列里，再复制一份进 export 就有两份，M3 改一处、export 忘一处就漂——上次来料模块大改就是这么来的。所以 `A-35` 直接从 M3 的 P1 行读，02 逐条给它找下落（进 M4 流程，或进 M6 后置批次并写明理由与兜底），找不到才红。**P1 允许不做，不许没下落。**

### 执行留痕（每一步都要留，不是可选项）

`_state.json` 记**产物真相**（六步做到哪、谁签的字）；`_run/` 记**这一轮怎么干的**（目标原句、规划、每步意图）。两层不许合并，两个都不许手改——只经 `harness.py` 改。命令与字段以 `$SUITE/_design/HARNESS.md` §5 为准，本文不抄第二份。

两个词别混用：`step` 记的是一**步**，`plan` 里的一项是**子任务**（`A1`~`A3`）。一个子任务动辄十几步，**步数不等于进度**——别拿步数当勾数。

**① 对话可见：进度块贴进回复正文，不依赖任何界面**

用户要在对话里看见跑到哪了。**Task 工具在 skill 被调用时通常不显示**（依赖宿主 UI），所以进度的落点只能是文字：

1. 每次 `next` / `step` 之后，跑一次 `next --brief`，把返回的 3 行**原样贴进回复**，不概括、不省略：

```
── 1/3 ──────────────────────────────
A1 ✓  A2 ← 现在  A3
做 A2 角色 → M2-roles.md｜内含「角色表」 ｜ 账本 4 步
```

2. 开工贴一次、每完成一步再贴一次。用户看的是这个块，不是你的总结段落。
3. Task 工具（`TaskCreate`/`TaskUpdate`）能用就用，**不能用也不影响**——它是锦上添花，不是这套机制的落点。别因为它不显示就跳过进度块。
4. 块里的「← 现在」与「账本 N 步」是自检：`_run/` 推进了而块没变，就是你漏跑了 `next --brief`。
5. 进度块不是证据。做完没做完看产物文件与 `_state.json`；块只负责让人看见。

**② 开工前跑 `next`，这是固定初衷的唯一入口**

项目还没有 `_run/` 时先 `init --dir analysis/<产品>/ --goal "<目标原句>" --auto --stage 1`；之后每次会话第一件事、以及每完成一个子任务之后，都跑一次 `next --dir analysis/<产品>/`。它打目标原句 + 当前位置 + 下一步 + 三条约束。不许凭记忆说"上次做到 A2"——`--status` 管判据，`next` 管目标和链路，谁也替不了谁。

**③ 每完成一个有产出的动作，跑 `step`**

| 算一步 | 不算一步 |
|---|---|
| 读一份原始材料并**得出结论**、写或改了一个产物文件、跑了一次校验并**解释了结果**、开了一次评审 | 纯检索、grep 找位置、翻目录、再跑一遍 `--status` |

`--intent` 写**判断**不写动作：「从原话里看出真问题不是缺按钮，是没人对留样负责」，而不是「读了 M1 参考」。将来复盘全靠这一列。
`--tool` / `--args` 必填（填你真跑的那个工具和关键参数，它同时是循环检测的依据），`--verdict` 默认 `ok`；产物不满足 `doneWhen` 记 `fail`；做了本段不该做的事记 `drift`。

子任务要标完成，**四样一起给，缺一样就等于没给**：`--done --taskId A2 --out M2-roles.md`，且 `M2-roles.md` 必须真的存在、`doneWhen.contains` 里的串（如「角色表」）必须真的出现。缺文件或缺串都 exit 6，但那是**防呆**，不是验收——验收仍是 `check_analysis.py` 那 24 条。只给 `--taskId` 也会 exit 6，那不是"工具不好用"，是这步还没做完。

**④ 每积累 2 步做一次里程碑自检**

`milestoneEvery` 到了就跑 `milestone --gap "..."`。`--gap` 写**这一轮产出对顶层目标还差什么**，"暂无""已对齐"算空话，判 exit 3、不计自检。自检只回答"偏没偏"，**不回答"完没完"**——它不给任何子任务打勾，别指望跑它把 A2 标完。本段的真例子：

> 场景表把留样漏了，M2 里也没有留样员的岗位，差一个角色的闭环。

**⑤ 跳步、偏离、循环，三种动作**

| 情况 | 退出码 | 动作 |
|---|---|---|
| 遗忘（跳步） | 4 | 读 `next` 的注入块，回到它说的那步，**不要重开** |
| 偏离（意图与目标不沾） | 0 / 3 | 单次只记 `goalAligned:false` 并 WARN、**放行**（真实发现常常一开始看着不沾），第 2 次仍放行，**第 3 次**才判偏离 exit 3；那时停手，把当前动作和目标原句各念一遍。真要加步骤 → `amend --add ... --why ... [--stage N] [--done-file <产物>]`，对不齐目标会被硬拒；没给 `--done-file` 的新步骤，完成时只认 `--out` 指向的文件存在 |
| 循环（同一动作第 3 次） | 2 | **立刻停**，不许换措辞重试。读 `log --tail 10`，判断是工具用错还是这步本来就做不了，写进 `blocked` 交给用户 |

**禁令**：`blocked` 之后不许自己 `--force-unblock`，必须用户确认过才能解。死循环之所以发生，就是因为模型相信"再试一次就对"。

## 三、M3 是唯一的硬闸门：五重

喊「场景没遗漏」不算数。`_state.json` 里要有五样东西（`A-25`）：

| 重 | 字段 | 挡什么 |
|---|---|---|
| ① 有人 | `confirmations.M3.by` 非空且不含 AI/模型/助手/Claude/GPT | 模型替用户签字 |
| ② 有时 | `.at` 是合法 ISO8601 且不在未来 | 时间写到未来，mtime 判据恒绿 |
| ③ 有据 | `.quote` ≥4 字，含 `S\d`／维度名／「没遗漏」／≥2 个业务实词 | 用一句「好的」冒充确认 |
| ④ 对版 | `.contentHash` = M3 去掉「确认记录」节后的 sha256 前 12 位 | **确认后又偷偷改场景表**——mtime 挡不住，hash 挡得住 |
| ⑤ 未跳步 | `M4` 不存在，或 mtime ≥ `M3.at` | 先写完第 4 步再回头补签 |

拦下时照这个句式回用户，不要自己找台阶：

```
M3 闸门未通过：[具体哪一重]。场景表共 16 条，其中 P0 6 条，待确认 4 条。
请回我一句「场景没遗漏，可以继续」，并确认这 4 条待确认怎么定，我再往下做第 4 步。
```

穷举的判法只有一条：**每个格子都有交代**。82 格是脚本按取值表实时求和出来的（`Σ 启用维度的取值数`），关掉一维分母自动变，不认手写数字。空格 0、排除 ≤40%、场景 ≥15 条、P0 ≥5 条、待确认 ≤7 格。
