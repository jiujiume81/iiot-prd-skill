# M2 角色：六字段照抄，另加一张现实性核对

## 六字段（用户给的结构，列名与列序一个字不改）

| 列 | 写法 | 反面 |
|---|---|---|
| 角色名称 | 岗位名，不用人名（「取样员」不是「老张」） | 「相关人员」 |
| 角色目标 | 他要达成什么，不是系统要他做什么 | 「完成检验」 |
| 使用频率 | 必须带数值：`40 次/天`、`2 次/周`、`1 次/月` | 「高频」「经常」 |
| 关注的信息 | 他做判断要看哪几个字段 | 「所有相关信息」 |
| 可能的操作权限 | 分成「能做 / 不能做」两段写 | 「管理员权限」 |
| 和其他角色的关系 | 上游是谁、下游是谁 | 「协作关系」 |

`A-10` 判：≥3 行，六列逐字且顺序一致。`A-11` 判：频率列必须含「次」和 `/天`、`/周`、`/月` 之一。

## 现实性核对：为什么单开一张表

六字段回答「这个角色在工作里做什么」，核对表回答「这个角色在系统里是否成立」。两个问题混一张表，用户会以为你在改他给的结构。

| 列 | 只允许写 |
|---|---|
| 角色名称 | 与角色表逐字一致 |
| 是否真实存在 | `是（N 人）` / `否（实际由 X 兼任）` |
| 与其他角色是否同一人 | `否` / `与 X 同一人（N 人重叠）` |
| 由此产生的系统约束 | 一条可校验规则：要么可做四眼，要么必须允许兼岗 |

`A-12` 判：行数必须等于角色表行数；标「否」的行必须写系统约束。

### 两个真实反例

**反例 1：质量总监是空的。** 设了二级审批，实际由质量工程师兼任。六字段表全对（权限、目标、关注信息都没问题），上线后所有单子卡在同一个人手上，比线下还慢。核对表写一行「否（由质量工程师老张兼任）/ 与 u-qa 完全同一人（1/1）/ 二级审批必须可关闭」，这个设计当场就废了。

**反例 2：取样员与保管员 3 人重叠。** 「取样人不得是收货人」看着很对，一落地一半单子做不了。真正能做的是「审核人不得是取样人」——差别只有在这张表里才看得见。

## 缺席的角色：系统外的四种人

`A-13` 判：≥2 行，每行必须写「系统必须为他留什么出口」。

| 角色 | 为什么不在系统里 | 典型出口 |
|---|---|---|
| 供应商 | 不开账号，怕数据外泄 | 报告 PDF + 二维码验真页（只读、免登录） |
| 客户 / 审计 | 一年来一两次 | 按单号穿透 + 导出 Excel 带限值快照 |
| 财务 | 只用结果，不进流程 | 让步接收月度清单，含金额 |
| 班组长 | 有审批但系统里没有角色 | 移动端只读看板 + 电话授权码 |

**为什么必须有这一节**：缺席的角色会用「打电话、发微信、拍照」的方式参与系统，这本身就是需求。不写出口，上线后他们就会绕过系统找人对私聊。

## 角色关系：图 + 三条硬约束

`A-14` 判（WARN）：图下方 ≥3 条硬约束，每条点名具体角色。

不合格：「注意权限隔离」「做好角色边界」——这类话任何项目都能用。
合格：「质量经理只有 1 人，夜班必须允许检验工程师代签，否则夜班让步单会卡到第二天」。
