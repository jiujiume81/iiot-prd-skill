# M6 对抗评审：四个角色，各 10 问

## 为什么默认加「现场使用者」

| 理由 | 说明 |
|---|---|
| 问了一定被拒 | 用户的心智模型里评审就是研发/测试/业务三方，「现场」不在他脑子里 |
| 成本最低命中率最高 | 10 个问题两分钟能写完，抓的是另外三方结构性抓不到的 |
| 制造业最贵的失败不是功能不对 | 功能不对测试能测出来；「上线后现场不用」只有现场视角能提前发现 |

执行方式：**不问，但告知**。M6 开头写一行说明，用户明确说不要，就把该节写成 `waived：原因`（`A-50` 保留该节 + `A-50b` WARN），并在风险表加一条。

## 四个角色的提问角度

| 角色 | 只许问 | 例子 |
|---|---|---|
| 资深研发 | 状态、并发、幂等、数据模型、事务边界 | 「S2 的待检冻结谁来解冻，解冻失败会不会永久卡住？」 |
| 测试负责人 | 可断言性、边界、异常路径、数据一致性 | 「断网补传重复提交两条，幂等键用哪个字段？」 |
| 业务负责人 | 时效、成本、编制、合规、客户影响 | 「判定从 4 小时压到多久，这个数写进验收了吗？」 |
| 现场使用者 | 手部状态、环境、光线噪音、姿势、班次、纸笔、工具更换、时间压力 | 「戴棉手套点这个 32px 的按钮，两次点不中怎么办？」 |

**现场使用者的 8 个角度**（问题必须落在这些条件上，否则就是研发问题换了个署名）：

| 角度 | 例子 |
|---|---|
| 手部状态 | 戴棉手套，这个按钮点得中吗 |
| 环境 | 货场只有 2 格 4G，这单能不能先存着 |
| 光线与噪音 | 车间 85 分贝，提示音听得见吗 |
| 站位与姿势 | 一手拿 PDA 一手翻货，两只手都不空 |
| 班次 | 夜班只有 1 个人，卡住了找谁 |
| 纸笔与口头 | 这一步不做系统，我用纸条记着行不行 |
| 工具更换 | 换了扫码枪型号，要不要改 |
| 时间压力 | 30 分钟内要卸完一车，你这个流程几步 |

`A-51` 判：每节 ≥10 条，每条含问号且点名具体对象（S 编号 / P 级 / 具体状态 / ≥12 字的完整问题）。
`A-52` 判：含「建议/优化/提升/加强/注意/关注」且没有问号的，直接红——那是结论不是问题。

## 风险表：恰好 5 条，按「多久会爆」排序

`A-53` 判：恰好 5 行；「上线后多久会爆」必须是时间量（第 N 次 / N 天 / 第一次月结 / 上线即爆）。

| 不合格 | 合格 |
|---|---|
| 高 | 第 1 次卸货 |
| 中 | 第一次月结 |
| 较大 | 第 1 个月 |

排序规则：先爆的排前面。第 1 次使用就爆的风险，比「半年后数据量上来才爆」重要得多——前者决定系统能不能活过试用期。

## 结论：二选一 + 恰好 3 件前置事项

`A-54` 判：出现「能开工」或「不能开工」（「不能开工」优先匹配），且下方编号项恰好 3 条。

| 不合格 | 合格 |
|---|---|
| 基本可行，注意风险 | **能开工**。必须先解决的 3 件事：1… 2… 3… |
| 建议分阶段推进 | **不能开工**。三个前置条件没满足：1… 2… 3… |

为什么恰好 3 条：超过 3 条等于没排序，用户记不住也不会做；少于 3 条说明你只看到表面。

## 评审不是夸，也不是清单罗列

| 表现 | 病因 | 判据 |
|---|---|---|
| 「建议加强权限校验」 | 被训练成"有帮助"，挑刺像是不友好 | `A-52` 无问号即红 |
| 「性能如何？」 | 没点名对象，问谁都答得上 | `A-51` 必须含 S 编号/状态/完整问题 |
| 40 条问题全是研发视角 | 只从自己熟的领域想 | 四节分开判，缺一节红 |
