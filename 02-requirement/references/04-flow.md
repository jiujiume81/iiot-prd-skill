# M4 业务流程：状态必须写成 from → to

## 主流程九列

| 列 | 写法 | `A-30` 判什么 |
|---|---|---|
| 步 | 1、2、3… | 空格子 |
| 步骤 | 动词开头，一件事一行 | 空格子 |
| 触发者 | 角色名 / 系统 / 设备（PLC、扫码枪） | 空格子 |
| 系统判断 | 进入这一步的 guard 条件，写成可断言的规则 | 空格子 |
| 输入 | 从上一步拿到的单据或数据 | 空格子 |
| 输出 | 交给下一步的东西 | 空格子 |
| 状态变化 | `待取样 → 已取样` | 不匹配 `^\S+\s*→\s*\S+$` 即红 |
| 批量粒度 | 单条 / 批（N 条） / 全量 | 全表没有「批」即红（`A-33`） |
| 对应场景 | S 编号 | P0 场景没出现在任何一行即红（`A-32`） |

`A-30` 还要求 ≥6 行。少于 6 行通常意味着把三个步骤合并成了「然后系统处理」。

## 状态集必须闭合

`A-31` 判两件事：

1. 主流程里出现的每个状态，都要在状态机表的「状态」或「→ 目标状态」列里出现；
2. 状态机里不能有只进不出的死状态。

| 现象 | 说明 |
|---|---|
| 流程写「待检冻结」，状态机没这个状态 | 一定是中间状态被漏了，单据会卡住 |
| 状态机有「待确认」但没有任何出边 | 复检完了不知道去哪，等于永久挂起 |

## 分支流程：只写分叉，不重画

| 列 | 写法 |
|---|---|
| 分支 | 一句话命名（「急用料先入库、判定后补」） |
| 从第几步分叉 | 数字 |
| 条件 | 可断言（「产线停线，且质量经理 15 分钟内批准」） |
| 去向 | 「回到第 N 步」或「结束」或「并行走到第 N 步」 |
| 对应场景 | S 编号 |

## 泳道：比例即判据

纵向步号，横向角色，每个泳道的节点数应与该角色使用频率成正比。如果一个只出现 2 次/月的角色占了半个泳道，说明流程是照组织架构画的，不是照工作流画的。

## 断点：上线后用户会怎么绕过

`A-34` 判：≥1 行，「上线后用户可能怎么绕过」非空。

| 断点位置 | 现在没系统时靠什么完成 | 上线后可能怎么绕过 |
|---|---|---|
| 第 2 步取样 | 纸笔记在送货单背面 | 货场没信号就不录，晚上一次性补录，漏批 |
| 第 6 步让步批准 | 质量经理电话口头同意 | 电话同意后系统没记录，出货按「已放行」处理 |

**断点的定义**：流程里某一步在现实中是靠人脑、纸条、电话撑着的，系统上线后这层支撑消失，用户会自己找替代。写不出断点的流程，说明没去现场看过。

## 常见错法

| 错法 | 为什么不行 | 改法 |
|---|---|---|
| 「提交后状态更新」 | 推不出按钮可用性，也推不出谁能操作 | `待判定 → 已放行` |
| 「系统处理」当一步 | 没有触发者、没有判断条件，测试无法断言 | 拆成「校验标准有效期」+「生成判定结论」 |
| 主流程 20 步 | 页面画不下，也没人看 | 合并同类项，分支移到分支表 |
| 状态名用「处理中」 | 太泛，三个环节都叫处理中 | 按动作命名：取样中 / 待判定 / 待确认 |
