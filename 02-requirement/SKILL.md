> **路径约定**：`$SUITE` = 套件根（同时含 `01-business/`、`02-requirement/`、`03-prototype/`、`shared/` 的那一层）。

### 执行留痕（每步必做）

`_state.json` 记**产物真相**，`_run/` 记**这一轮怎么干的**；两层不许合并，都不许手改。完整规则见 `$SUITE/shared/references/08-run-contract.md`，这里只留不能省的五条：

1. **开工先 `next`**：打目标原句 + 当前位置 + 下一步 + 三条约束。不许凭记忆说"上次做到 B3"。
2. **每步贴进度块**：`next --brief` 的 3 行**原样贴进回复**，不概括。
3. **有产出才记一步**：读上游并得出结论 / 写改产物 / 跑校验并解释结果 / 开评审算一步；纯检索、grep、翻目录不算。`--intent` 写**判断**不写动作。
4. **完成由产物决定**：`step --done --taskId B2 --out M5-exceptions.md`，文件必须真存在且 `doneWhen.contains` 的串真出现，否则 exit 6。里程碑自检**只读**，不给任务打勾。
5. **三种异常**：exit 4 跳步 → 读注入块回正，不重开；exit 3 偏离 → 单次放行、连 3 次才拦，加步骤走 `amend --why`；exit 2 循环 → **立刻停，不许换说法重试**。

`blocked` 后不许自己 `--force-unblock`——死循环之所以发生，就是模型相信"再试一次就对"。

## 三、落契约的六条硬线

契约是唯一的下游接口，写歪一条 03 全部白做。

| # | 硬线 | 怎么写 | 谁判红 |
|---|---|---|---|
| 1 | **一个动作 = 一个状态 = 一条命令** | 待排查/待分析/待下发/措施执行中/待验证/待审批 各一条 `capability`，各自带 `actor` | `L2-54`~`58` |
| 2 | **状态机端点不许悬空** | 每个 `from`/`to` 在状态集里能找到；非终态必须有出向命令，否则单据永久卡住 | `L2-57` |
| 3 | **四眼原则** | `stage` 为 `submit` 与 `verify` 的命令 `actor` 交集必须为空；一人多角色须显式 `sameActorOk` | 四眼判据 |
| 4 | **EARS 六字段不能省，且必须有非法路径** | 角色（岗位不用人名）/触发/规则/状态机/预期（单一响应）/验收（≥1 条 `kind:"illegal"`：状态不符、权限不足、并发冲突） | `L2-34` |
| 5 | **字段主档只登记被点名过的字段** | M1/M3/M5 出现过的业务字段才进 `fieldCatalog`，`dataSources` 要能解析到源表 | 字段主档 |
| 6 | **切片要能独立验收** | 每批有范围、有依赖、无成环；一次做完必然后几页糊 | `P-01`~`11` |

**两处是 03 的活，本段不许写**：`capabilities[].ui`（`kind`/`entry`/`title`/`fields`，属渲染决策）；`pages[].componentTree`/`prd`/`interactions`（本段只给骨架 `id`/`moduleId`/`target`/`route`/`title`/`layout`/`entity`）。

### M4 必须有「P1 未上流程」专节

01 只把 P0 交过来，P1 会在这里**静默消失**——不报错、没人问、上线才发现缺一块。规矩：**允许不上流程，不许没有下落。**

每个 P1 只有两条去向：进流程（正常写），或后置（写进 `M4` 的「P1 未上流程」专节，说明为什么不在这批 + 落到哪一步兜底）。

```markdown
## P1 未上流程
| 场景 | 为什么不在这批 | 落到哪一步兜底 |
| S-11 退货复检 | 频次 2 次/月，本批只做日频 | 走线下纸质单，M5 异常 7 记录补录 |
```

`A-35` 从 M3 的 P1 行逐条找下落，找不到就红。P1 清单不另存一份——M3 的优先级列是唯一源。

### 判据索引（21 条本段）

`A-30`~`34` M4（`X → Y`、状态集闭合、P0 上流程、批量粒度、断点）｜`A-40`~`44` M5（12 类覆盖、影响量化、降级动作、可追溯、补数口径）｜`A-50`/`A-50b`/`A-51`~`54` M6（四角色 ≥10 问、疑问句、风险恰 5 条、结论二选一）｜`A-35` P1 有下落｜`A-36` 落契约不早于评审签署｜`A-67` 语义半边纯净度｜`A-68` 签收后 md 被改。

**`A-67` 一句话**：签收前含渲染键 = 红；签收后 = 黄（那是 03 追加的）；签收版本身含渲染键 = 红（防篡改）；md 变了则签收失效、含键即红。`--seal` 时一律不降级。`A-68` 与 `A-67` 共用同一个 `sealed` 快照——**判据守的时点只能有一个开关**。
