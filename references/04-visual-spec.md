# 视觉与组件规范

> 工业软件的审美标准不是"好看"，是**长时间盯屏不累、数据比装饰显眼、状态一眼能分辨**。这份文档把这三条翻译成可判定的规则，避免每次改都靠吵。

## 1 设计令牌（与 `styles.css` 的 `:root` 一一对应）

### 1.1 色板

| 令牌 | 值 | 用途 | 禁止用于 |
|---|---|---|---|
| `--ink-950` | `#07161D` | 浮层遮罩底、深色区最深一级 | 大面积背景 |
| `--ink-900` | `#0B2028` | 导航主体 | 正文背景（文字对比度不足） |
| `--ink-800` | `#123039` | 导航分组头、悬停 | — |
| `--ink-700` | `#1B4450` | 导航活动项底 | — |
| `--brand-700` | `#075C6B` | 主按钮 hover | — |
| `--brand-600` | `#0A7183` | 主按钮、当前页签下划线、聚焦环 | **状态标记**（会和 ok/warn 抢） |
| `--brand-400` | `#2AA3B3` | 导航活动指示条、进度点 | 正文文字（对比度 3.2:1 不足） |
| `--brand-50` | `#EFF8FA` | 选中行底、可编辑区聚焦底 | 大面积卡片底 |
| `--ok-600` / `--ok-50` | `#1B7A57` / `#E8F5EF` | 合格、已归档、通过 | 主按钮 |
| `--warn-600` / `--warn-50` | `#9A6508` / `#FBF2DF` | 待取样、待审核、临期 | 主按钮 |
| `--danger-600` / `--danger-50` | `#B23A31` / `#FBEcea` | 不合格、驳回、断链 | 装饰、图标默认色 |
| `--info-600` / `--info-50` | `#37597E` / `#EDF2F8` | 提示、说明性标签 | 状态标记（第四种状态色会稀释前三种） |
| `--text-1/2/3` | `#0F1F27` / `#4B5F69` / `#7E919B` | 主文字 / 次要 / 辅助 | — |
| `--page` / `--surface` | `#F2F6F7` / `#FFFFFF` | 工作区底 / 卡片 | — |
| `--line` / `--line-2` | `#E3EBED` / `#EFF4F5` | 区块分割 / 表内分割 | — |

**为什么主色是青蓝不是蓝**：质检页上同时存在「待审核（琥珀）」和「不合格（红）」。再压一个高饱和蓝主按钮，三种颜色在同一视觉层级互相抢，用户扫视时找不到结论。青蓝 `#0A7183` 在色相上离琥珀（38°）和红（8°）都远（188°），作为"动作色"不抢"结论色"。

**为什么状态色只有三种**：合格 / 待处理 / 不合格。第四种（如"已取消"）用 `--text-3` 灰，不用新颜色——每加一种状态色，前三种的辨识度就降一档。

### 1.2 字号与行高

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-lg` | 16px | 页面标题（一页最多 1 处） |
| `--fs-md` | 14px | 区块标题、按钮、强调数字 |
| `--fs-sm` | 13px | 正文、表单值 |
| `--fs-xs` | 12px | 表格正文、标签、辅助说明 |
| 展示字号 | 26px | **仅限 KPI 大数字**；不进令牌，因为它只服务一种组件 |

**一屏内字号种类 ≤ 4（KPI 的 26px 不计入）**。这条是硬规则：出现第 5 种（比如 11px、15px）通常是在"因为放不下所以缩一点"，而那只说明该删内容，不该缩字。

26px 单独开一个例外，是因为指标卡的数字必须在一屏里第一眼被看到，16px 做不到。但**一屏只允许一组 KPI**——两排 26px 数字会互相稀释，反而谁也不显眼。

### 1.3 尺寸与栅格

| 令牌 | 值 | 说明 |
|---|---|---|
| `--h-header` | 52px | 页头 |
| `--h-tabs` | 38px | 页签条 |
| `--h-toolbar` | 44px | 工具条 |
| `--h-footer` | 44px | 分页/页脚 |
| `--w-sider` | 232px | 导航展开宽（收起 56px） |
| `--row-h` | 34px | 表格行高 |
| `--r-sm/md/lg/xl` | 4 / 6 / 10 / 14px | 标签 / 控件 / 卡片 / 浮层 |

间距一律 4 的倍数（8px 基准取整）。出现 5px、7px、13px 这类奇数间距，说明是拼出来的而不是排出来的。

## 2 PC 布局规范

### 2.1 作业型列表页（最常见的页面类型）

```
┌─ 页头 52：面包屑 + 标题 + 右侧全局动作 ────────────────┐
├─ 页签 38（可选）──────────────────────────────────┤
├─ 工具条 44：左侧批量动作 · 右侧刷新/列设置/导出 ────────┤
├─ 筛选区：3 列 × 2 行，label 68 右对齐，按钮组贴右上 ────┤
├─ 表格：全宽，表头 sticky，行高 34，行内操作 ────────────┤
└─ 页脚 44：已选 N 项 · 共 M 条 · 分页 ──────────────────┘
```

五条硬规则：

1. **列表页顶部 0 个指标卡。** 指标走独立统计页。列表页放指标卡的后果是：每加一个指标，表格可见行数就少 2 行，而列表页的使用者 80% 时间在看表格。
2. **筛选区 3 列封顶。** 4 列以上会挤成两行半，视觉断裂。字段多于 6 个时，"高级筛选"折叠。
3. **表格必须 `table-layout: fixed` 且每列给 width。** 少给一列 → L2-17 红。不给宽度的列在 fixed 布局下宽度为 0，实际表现是"这一列神秘消失"。
4. **列宽合计 ≤ 内容区宽**。1440 − 232 = 1208px 是笔记本上限；1920 − 232 = 1688 是工位机。给 1440 设计就要按 1208 排——11 列合计 1196 是这么来的（见 `example-01`）。
5. **行内操作不跳详情再返回。** 高频动作（审核、打印）直接在行内完成，详情页是给"要看全貌"的人用的。跳转一次平均 6~8 秒，一天 20 次就是 2 分钟。

### 2.2 详情页

字段按**业务含义分组**，不按数据库字段顺序分组。28 个字段平铺的页面，工程师找不到"标准限值"在哪。

```
基本信息（到货单号 / 物料 / 供应商 / 数量）      ← 4~6 项，只读
取样记录（取样人 / 时间 / 数量 / 外观）          ← 表格，1~N 条
判定依据（标准版本 / 限值 / 实测值 / 结论）      ← 逐项对比，超限标红
操作记录（谁在什么时候做了什么）                  ← 时间线
```

四组以内用平铺 + 分割线；五组以上用左侧锚点导航。

### 2.3 状态条

单据类页面必须有状态条，四个节点一行排开，当前节点用 `--brand-400` 指示条，已完成用 `--ok-600`，未达用 `--text-3`。状态条的价值不是装饰——它让用户不用点开任何东西就知道"这单走到哪了"。

## 3 PDA 规范

```
┌─ 状态栏 30：时间 · 信号 · 电量 · 离线角标 ───────┐
├─ 头部 44：返回 · 页面标题 · 待上传数 ────────────┤
├─ 扫码条 56：常驻、自动聚焦、扫不出时切手输 ───────┤
├─ 内容区：单列卡片，间距 10，卡片内边距 12 ────────┤
└─ 底部主操作：48 主按钮 + 一行说明文字 ───────────┘
```

五条硬规则：

1. **390 × 844**。不是"随便的手机宽"，是工业手持机的实际可视区。按 375 设计会在真机上右边被裁 15px。
2. **一屏一个主操作**（`BigAction`，L2-49）。两个主按钮等于没有主按钮。
3. **触控目标 ≥ 44px**。戴手套后有效触控面积会缩到 60%，36px 的按钮在现场基本点不中。
4. **必须声明 `onlineOnly` 或 `offline`**（L2-48）。声明 `offline` 就必须有离线暂存 + 待上传角标 + 冲突处理，不是一句"支持离线"。
5. **禁止引用 `pc-*` 组件**（L2-15）。PC 的 34px 行高表格在 390 宽上必然横滚。

PDA 上的信息密度要主动降低：一屏显示 1 个任务的完整信息，而不是 5 个任务的摘要。现场用户不需要"总览"，需要"这一垛怎么办"。

## 4 组件选型决策

组件库有 51 个组件，选错比没有更糟。给出四条决策规则：

| 场景 | 选择 | 不要用 | 理由 |
|---|---|---|---|
| 状态标记 | `Tag`（带底色） | 纯文字 | 纯文字状态在 11 列表格里扫不出来 |
| 数量/金额 | `right` 对齐 + `num` 类型 | 左对齐 | 数字左对齐无法竖着比大小 |
| 2~4 个互斥选项 | `Segmented` | `Select` | 下拉要多一次点击，且看不到其他选项 |
| ≤ 5 个筛选项 | 平铺 | 折叠面板 | 折叠面板多一次点击，5 个以内不值得 |
| 危险动作 | 二次确认弹窗 + 红字说明后果 | 直接执行 / 只变红 | 红色只是提示，不是防护 |
| 长文本只读 | 展开/收起（默认收起 2 行） | 滚动条 | 内嵌滚动条在触控设备上不可用 |
| 空状态 | 说明 + 一个建议动作 | 只写"暂无数据" | "暂无数据"没告诉用户下一步做什么 |

**不确定时选简单的那个。** 组件的复杂度会以"每个页面都要处理它的边界情况"的方式复利。

## 5 审美的可判定部分

"好看"没法判定，但下面 8 条可以。这是评审时的检查表，不是风格偏好：

| # | 判据 | 检查方法 |
|---|---|---|
| 1 | 一屏内字号 ≤ 4 种（KPI 的 26px 另计，且最多一组） | 数 `font-size` 的不同取值 |
| 2 | 一屏内高饱和色 ≤ 3 种（不含灰阶） | 数饱和度 > 40% 的色相 |
| 3 | 正文对比度 ≥ 4.5:1，辅助文字 ≥ 3:1 | 取色算 |
| 4 | 所有间距是 4 的倍数 | 抽查 10 个 margin/padding |
| 5 | 表格一屏可见 ≥ 12 行（900px 高） | 数可见行 |
| 6 | 主色只出现在可点击/当前态元素上 | 扫一遍主色块 |
| 7 | 同一视觉层级内只有一种强调方式（底色 / 边框 / 加粗，不叠加） | 看重点单元格 |
| 8 | 空态、加载态、错误态都有设计，不是白屏 | 切四态截图 |

第 5 条最容易被忽略：行高从 34 加到 40，一屏就少 3 行，一个月后没人记得为什么表格"看起来松了但效率低了"。

## 6 五个典型反例

| 反例 | 症状 | 病因 | 修法 |
|---|---|---|---|
| 指标卡堆满列表页顶部 | 表格只剩 8 行可见 | 觉得"数据要多展示" | 指标移到统计页；列表页只留 1 行关键计数 |
| 每个按钮都用主色 | 满屏青蓝，找不到主操作 | 把"可点击"等同于"重要" | 主色只给每屏 1 个主动作，其余用次按钮 |
| 表格同时有隔行变色 + 全边框 + hover 高亮 | 视觉噪声大，扫视困难 | 三重区分手段叠加 | 只留 `--line-2` 横向分割线 + hover 底色 |
| 空图标框占位 | 导航项前面一个空方块 | 图标资源缺失但布局留了位 | 要么给真图标，要么去掉位置（收窄缩进） |
| 全站圆角 8px + 卡片阴影 3 级 | "网页感"重，不像工具 | 移动端审美迁移到桌面 | 圆角 4/6 为主，阴影只用于浮层 |

## 7 交付给开发的注意事项

原型是**真实 DOM**，前端可以直接搬结构。三条约定让搬运不返工：

1. **class 名有语义**（`filter-fields`、`dt-row`、`big-action`），不是 `div1`/`wrapper-2`；
2. **组件是 Vue options API**，`props` 定义在组件对象里，可以直接抽成 `.vue` 单文件；
3. **不依赖容器**。组件的渲染函数只吃 `props`，不吃全局 store——这样搬走时不用连带搬容器。
